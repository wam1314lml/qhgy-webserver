# 公会集结与签到活动前端

独立目录 `src/features/activities/` 可随配套后端模块迁移。本项目后端仓库 `J:\CodeBuddy\qhgy-web\qhgy-web/docs/ACTIVITIES.md` 是完整业务/API说明，`ACTIVITIES_MIGRATION.md` 是数据库与跨项目验收手册；迁移时携带这两份文件。

| 文件 | 职责 |
| --- | --- |
| `types.ts` | 公共配置、进度、领取记录契约 |
| `api.ts` | `/api/activities` 调用、未确认请求重试 ID、时间与奖励格式 |
| `ActivityWelfare.vue` | `type="guild_rally"` 或 `type="sign_in"` 的用户活动及奖励历史 |
| `GuildAllocation.vue` | 集结一键/两步分配，首日到账、角色启停、同步读条、补余量和中断重试 |
| `ActivityWelfare.css` | 活动卡片、进度、签到日历、奖励与移动端样式，迁移时必须携带 |
| `SignInCalendar.vue` / `.css` / `calendar.ts` | 整月奖励日历、跨月导航与累计奖励 |
| `RewardIcon.vue` | 点数金币（cash）、时钟（time）、卡密（card）SVG 图标 |
| `ActivityArtwork.vue` / `imageUpload.ts` | 默认主题图、后台图片预处理及预览 |
| `ActivityAdmin.vue` | 活动创建/编辑、配额、每日/累计奖励、规则锁定和到期删除，接收管理员 `token` |

外部接线：`WelfarePage.vue` 加两个活动标签；`AdminPanel.vue` 加仅管理员可见的活动管理；`QuotaSettings.vue` 指向活动管理；`ScriptConfig.vue` 普通配额弹窗提供活动入口并监听时长刷新；`TopNavBar.vue` 福利入口 new 与退出事件；`router/index.ts` 的福利权限允许管理员。

活动配额配置独立于普通套餐，分配成功才参与。玩家每档选择一种奖励：福利卡面额是**点数**、无限制兑换人；点数直接到账；时长单位为小时，必须选择当前网站账号下的未过期角色。签到按网站账号、北京时间每日一次，累计不要求连续；漏领的已签到奖励可在活动期内补领。

## 集结两步分配（2026-10-27）

- 角色未到期且公会完整时原按钮一次性分配；到期/缺公会时自动使用两步流程，有效角色也可勾选「公会信息不对，重新同步后参与」。
- 首次确认先到账1天并支付单日费用。首款向上取到小数点后两位，余款为总价减首款；60天/60点先1点后59点，3天/10点先3.34点后6.66点。总天数和总价与原套餐一致，整套完成才算一次分配及一个参与角色。
- 首日到账后显示「启动角色并刷新公会」和「已启动，刷新公会信息」。前者复用原角色启停接口，在线角色先停再启；后者只查询公会。等待时按步骤显示读条，每5秒读取服务端状态，3分钟未同步完成提示重试。
- 只有服务端确认新公会信息后才自动请求补足，状态接口不扣款，补款接口再次验证。客户端不提交公会/同步时间/金额。启动失败、未入盟、余款不足保留进度，刷新后从活动视图恢复，重试不会再扣首日。离开页面、退出或切号会取消等待和后续自动请求，已提交的事务由后端幂等处理。
- 首日是已购买并开始计时的配额；若等待到首日也到期，需先恢复角色运行条件再继续。活动停用或结束不能补款，已支付首日保留。部署需先后端完成 welfare_activity_allocations 缺表初始化，再前端；迁移须核对脚本的 player.unionUpdatedAt，不能用旧公会缓存冒充本次同步。

浏览器专项覆盖有效角色一键、到期先付一天、公会不对手动切换、授权失败重试、已有在线角色重启、刷新恢复、等待及自动补足、余款不足重试、离开页面取消自动补款，以及320/390像素读条和按钮布局。测试只用合成接口；真实脚本/Redis/MySQL 联调仍需部署前独立验收。

## 页面与到期管理（2026-10-27）

- 福利页使用浅雾色背景、深青公会进度、金色奖励提示；桌面分栏展示配额，手机自动纵向排列，保留原有日常/充值福利入口。
- 公会进度条以最高奖励人数固定为终点，各奖励节点按人数比例定位；例如2/5人奖励分别位于40%/100%，已有1人时填充20%。未达标节点空心，达标后金色实心并显示勾选；超额参与保持满条和原刻度，真实人数仍完整显示。
- 公会集结/签到选项卡按 `/summary.activeTypes` 独立显示：至少有一期已启用、未删除且正在进行的对应活动才开放；没有活动、停用、未开始、已结束均不显示入口。与角色数量、是否已签到/领完奖励和红点无关。
- 兼容旧摘要：`activeTypes` 缺失/格式错误或摘要接口不可用时，改从活动列表的 `enabled && status === 'active'` 推导类型；明确空数组不回退、401/403 不回退。列表中的已停用/未开始/已结束活动不打开入口，状态以服务端为准。新摘要正常时不额外读取列表。
- 活动查询失败显示「活动信息加载失败」及重试按钮，不能误报「暂无开放的福利活动」；暂时失败保留本账号最近成功状态，鉴权拒绝/退出则清空。旧请求在退出/切号后完成不能恢复原账号入口。无需数据库或后端代码变更即可修复旧摘要导致的选项卡及 new 消失。
- 首次加载后选择第一个开放页签；当前入口被关闭时自动切到其他开放福利，全部关闭显示空状态。开放新活动不打断正在浏览的有效页签。复用活动摘要的事件、聚焦和60秒轮询刷新，退出账号清空入口状态。
- 福利入口已取消红点，改用 `hasActiveActivities` 控制 `WelfareNavLabel` 右下角跳动的 `new`：公会集结或签到任一类型进行中便显示，已签到/奖励领完仍显示；仅剩充值抽奖次数不会显示。活动全部结束/停用或退出账号后移除。动效只移动标记，系统减少动态效果时静态展示。迁移时携带该组件、composable 与 TopNavBar 接线，沿用后端 `activeTypes`，无需数据库变更。
- 签到页只展示 `status=active` 的活动；停用、已结束及未开始的签到均隐藏，已领取奖励仍展示在历史中。后端也做相同过滤。
- 整月签到日历直接取服务端 `signIn.days` / `today`（北京时间），未开始的日期不会显示成漏签。每日奖励是活动期内每天签到后各领一次，累计奖励独立领取。
- 管理员列表根据服务端 `canDelete` 开放「删除活动」，需二次确认。公会集结、签到到期后都可删除；仅停用但未到期不能删除。状态/删除资格以服务端时间和事务校验为准。
- 删除是保留历史的逻辑删除，成功后刷新列表和活动摘要；卡密、点数、角色时长、领取历史不撤销。不要在前端清空历史来模拟删除。
- 管理员 API 增加 `DELETE /api/activities/admin/:id`，列表补充 `status` / `canDelete`。先发布配套后端并完成字段初始化，再更新前端。

前端不自行判定是否真正符合领奖资格，以服务端 rewardStates/canAllocate/canSignIn 为准；服务端仍会在写入时重新校验。活动时间 API 用 UTC 毫秒，显示与管理员输入均固定北京时间。已有参与的规则不能修改，标题/说明/启停与延后结束时间可改。

## 整月签到与活动背景（2026-10-27）

签到显示真实月份七列日历，支持活动覆盖月份间切换；活动结束零点不包含次日。每日格显示管理员配置的图标和数量，点击今天可签到，点击已签未领奖的日期可补领；未来、未签和活动外日期不可领取。每日多选项仍任选一项，累计奖励独立展示，手机端在日历下方。

签到要求当前网站账号名下至少有一个未过期角色；无角色、全部过期及恰好到期时禁止签到并显示原因。已签到的点数、卡密奖励仍可领取。领取时长必须选择名下未过期角色，并从原有效期累加；登录、网站账号状态及福利权限仍正常校验。

本项目默认不附带其他游戏的品牌图；管理员可上传自己的活动背景。 上传图按原比例完整显示，真实奖励始终由活动配置与日历决定。

管理员创建/编辑时可上传 PNG/JPEG/WebP（原文件最大 8 MB），浏览器缩至最长边 1920 并转 JPEG，再通过 `POST /api/activities/admin/backgrounds` 上传。后端重新校验、转码、存库，返回 `/api/activity-backgrounds/<hash>.jpg`。上传后点击「保存活动」生效，已有参与也能换图；上传失败保留原图，上传期间禁止保存或关闭编辑框。

`backgroundUrl=null`（或旧数据缺失）使用默认图，空字符串不显示图，其他值只允许服务端上传返回的地址。「恢复默认图片」「移除背景」分别对应前两者。图片只读接口是公开静态素材，写入仍需管理员及站点原有保护；图片应只包含可公开展示内容。

## 时长奖励有效期校验（2026-11-01）

公会集结、每日及累计签到的时长奖励只允许选择当前用户名下未过期角色；没有可选角色时显示绑定/开通/续期提示，并禁用确认。提交前再次检查目标角色，接口仍会锁定角色并校验归属和有效期；收到拒绝后刷新列表。点数和点数福利卡不增加此限制。

迁移携带 `rewardAccounts.ts` 与 `ActivityWelfare.vue`。运行 `node --test scripts/test-activity-rewards.mjs` 检查空/无效期限、过期边界、跨时区和续期恢复；浏览器脚本增加过期目标拦截及移动端提示验证。
